# 与 new-api 的功能差距分析

> 依据：new-api 公开 README 中的功能描述（2026-10）。**只比较功能，没有阅读或参考它的源代码**，以保持 TokenExchange 独立实现、MIT 许可的状态。

图例：✅ 已有　🟡 部分实现　❌ 没有　⛔ 当前架构（Vercel serverless）做不到

## 1. 接口与协议

| 能力 | new-api | 我们 | 说明 / 改进建议 |
|---|---|---|---|
| OpenAI Chat / Responses / Embeddings | ✅ | ✅ | |
| Anthropic Messages | ✅ | ✅ | |
| Gemini generateContent / stream | ✅ | ✅ | |
| **跨协议转换**（用 OpenAI SDK 调 Claude 等） | ✅ | ✅（P1） | **P1，价值最高。** 很多客户只用 OpenAI SDK。先做 Chat Completions → Anthropic Messages（含流式、工具调用），再做 → Gemini |
| 图像生成 / 编辑 `/v1/images/*` | ✅ | 🟡 生成（P2），无编辑 | P2。按张计费，需要"按次计价" |
| 语音 `/v1/audio/*`（TTS / 转写） | ✅ | ✅（P2） | P2。转写是 multipart 上传，受 4.5 MB 请求体限制 |

## 2. 计费

## 7. 建议的改进顺序

> 状态（2026-10）：P0、P1、P2 已完成（P0、P1 各经过一次独立 review 并修复了发现的问题），见上表标注。剩余：图像编辑、TPM / 并发限流、Passkey、邀请返利、更多语言、Realtime（需常驻进程）。

**P0（上线收费之前）**
1. 预扣费，防止并发请求透支余额
2. 按 key 限流（Upstash Redis）
3. 改密码 / 重置密码后让旧会话失效

**P1（上线后第一个月）**
4. OpenAI ↔ Anthropic 协议转换（让只用 OpenAI SDK 的客户也能调 Claude）
5. 渠道亲和（提高提示词缓存命中率）
6. 用户分组定价（批发客户、VIP）
7. GitHub / Google 登录；管理员两步验证
8. 审计日志、低余额邮件、渠道自动恢复

**P2 以后**：图像、音频、rerank、count_tokens 接口；阶梯价；兑换码；playground；多语言

## 8. 我们比 new-api 好的地方

- **MIT 许可**：可以闭源二次开发，没有署名要求
- **Serverless 部署**：零运维，冷启动快，按量付费
- **成本和毛利可见**：每个渠道有成本倍率，看板按来源（官方 / 云 / 转售）拆分毛利
- **来源级路由策略**：可以一键关闭某一类来源，或限定某个模型只走官方和云厂商
- **凭据加密**：上游 key 用 AES-256-GCM 加密存储；客户 key 只存哈希
- **计费有端到端测试覆盖**：每种协议、流式和非流式都有测试
